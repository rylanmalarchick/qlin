ONE LINE
--------
Compile a dynamic circuit so that its expected shot cost is as low as
possible. Precompile a fast path for the likely measurement outcomes
inside a budget, keep a correct generic fallback for the rest, and prove
a lower bound on what must stay runtime-decided.

4. FRAMING, TERMS, PROBLEM
==========================

Framing (matches the 2026-09-25 email to Charles Yuan)
------------------------------------------------------
The compiler treats mid-circuit measurement outcomes as an uncertainty
set. It precompiles and optimizes a fast path for every outcome inside a
budget. A correct generic fallback covers the rest. The runtime decides
only the branches that truly depend on a measured bit. Everything else is
fixed and checked at compile time. The device enters through a small cost
model that a measurement on that device can falsify.

Three ways to say what this is, for three audiences:

  PL          Speculative specialization with deoptimization, over a
              finite outcome set, with a soundness proof. Classic
              relatives: trace scheduling (Fisher 1981), superblocks
              (Hwu et al. 1993), profile-guided hot/cold splitting
              (Pettis and Hansen 1990), JIT deoptimization (Holzle,
              Chambers, Ungar 1992). The quantum twist: the "profile" is
              a distribution the physics gives you, and the fallback
              must resume from a quantum state it cannot inspect.
  Yuan        His Spire work (PLDI 2024) prices QUANTUM control flow
              (the quantum if) in T-complexity. qlin prices CLASSICAL
              control flow (feedforward) in latency and error. The
              deferred-measurement rewrite turns one into the other, so
              one cost model can choose between them per device.
  Hardware    Clique (Ravi et al. 2022) and the lazy decoder (Delfosse
              2020) split decoding into a cheap common-case path and a
              full fallback. qlin does the same split for the program,
              at compile time, not in the decoder.

Link to own prior work: specqec (arXiv:2607.13062) does runtime
predict/verify/recover for window decoding. qlin is the compile-time
side of the same idea.

Terms
-----
  b              the measured-bit vector, b in {0,1}^m, revealed one bit
                 at a time as the program runs.
  trace T(b)     the straight-line op sequence the source program runs
                 for outcome b.
  reference r    one fixed outcome vector: the most likely value of each
                 bit (for a loop: the "success" exit).
  M_t            outcome budget: all b with at most t bits different from
                 r. Size: sum over k = 0..t of C(m, k).
  dynamic core   ops whose identity or parameters depend on a measured
                 bit AFTER constant propagation, under a named move set.
  movable op     any other op inside a branch.
  move set       the rewrites qlin may apply:
                   hoist   move an op out of a branch when both arms
                           contain it
                   sink    move an op into both arms (duplicate)
                   merge   join equal suffixes of two arms
                   defer   deferred-measurement rewrite: replace a
                           classically controlled op by a quantum
                           controlled op and move the measurement later.
                           Costs a 2-qubit gate, and a fresh qubit if the
                           measured qubit is reset and reused.
                   unroll  unroll a measurement-bounded loop up to t
                           failed tries.
  M0             the move set {hoist, sink, merge, unroll}. No defer.
  fast path      code precompiled for outcomes in M_t, as a decision
                 tree over bit prefixes inside M_t.
  exit edge      the point where the running prefix leaves M_t (weight
                 becomes t + 1).
  compensation   code on an exit edge that puts the machine into the
                 state the fallback expects (classical registers, and
                 later qubit layout).
  fallback       generic code, correct for every outcome, with one entry
                 point per exit edge.

Problem statement
-----------------
Input: a program P, a device cost model C, a reference r, a budget t, and
a code-size limit S (control hardware holds a finite number of
precompiled segments).

Output: a fast path F over M_t, a fallback G, and compensation code on
every exit edge.

Objective: minimize expected cost

  E[cost] = sum over b in M_t of p(b) * C(F, b)
          + P(b not in M_t) * (C(exit) + C(G))

subject to size(F) <= S. The objective is cost, not core size. With
defer, the core can shrink to zero while the cost goes up (claim C2).

Correctness (the soundness claim):
  (S1) For every b in M_t, F run on b gives the same channel as T(b).
  (S2) For every b not in M_t, the prefix of F up to the exit edge, then
       the compensation, then G, gives the same channel as T(b).
  (S3) Every rewrite in the move set preserves the output distribution.

Section 8 gives the check method for each claim.

Where the budget pays and where it does not (state this in the write-up)
-------------------------------------------------------------------------
  - Pays: syndrome extraction plus correction (most syndromes have low
    weight). Repeat-until-success (a few failed tries cover most mass).
  - Neutral: iQPE and iQFT. Outcomes depend on the input phase. For an
    exact phase, BQCP-style propagation may remove the branches first.
  - Does not pay: teleportation. The two bits are uniform. Here m = 2, so
    t = 2 covers all 4 outcomes. The core bound and the defer choice are
    the point, not the budget.

7. EVALUATION PROTOCOL
======================
Benchmark set: section 6, steps 1.3 and 1.4.

Metrics, per benchmark, per baseline, per t. Phase 1 metrics come from
`qlin stats`, one implementation for every tool:
  qubits  qubit count.
  m       live measure ops (a matched pair counts once).
  gates   gate ops in the program text, in every arm. 2q: arity >= 2.
  dyn     leaf ops inside an arm of a dynamic If or the body of a
          dynamic loop.
  ff      dynamic conditions: If conditions and loop exits that do not
          fold to a constant.
  core_b  core leaves under M0 in dynamic If arms.
  core_l  leaves in dynamic loop bodies. They repeat on a measured bit.
  mov     matched leaf pairs that hoist or merge out of a dynamic If.
  dead    leaves in arms that constant folding proves never run.
Phase 2 and later add:
  E[lat]  expected shot latency under cost model C and prior p(b).
  size    fast-path size, in ops and in precompiled segments.
  exit    exit probability P(b not in M_t).
  cost+   extra 2-qubit gates and extra qubits from defer.
  ctime   compile time.
Baselines are reported on their own metrics too (gate count, depth, ff
count). No table shows only a metric that only qlin wins on.

Pipelines in Phase 1: source, bqcp (max_amplitudes 512, max_branches 4),
qiskit_o0 and qiskit_o3 (basis rz sx x cx, no coupling map), tket
(FullPeepholeOptimise, no swaps). The semantics guard compares output
distributions from |0...0> on programs with <= 12 qubits.

Labels on every number: modeled, emulated, or measured.


8. SOUNDNESS CHECK METHOD
=========================
Per-outcome trace equivalence checks hoist, sink, merge, and unroll.
It does NOT check defer, because defer moves a measurement and changes
the trace itself. So:

  - Moves in M0: for each b, compare the op sequence of F (or of the
    prefix, compensation, and G) against T(b). Equal traces imply equal
    channels. Sound, not complete.
  - Defer: compare channels directly. On m <= 12, compare output
    distributions from the state-vector simulator for every input basis
    state and every b. Cross-check with MQT QCEC (2106.01099) or Hybrid
    Path-Sums (2604.24578), which covers the classical-to-quantum
    control rewrite.
  - Every check has a negative test: a planted wrong rewrite that the
    check must reject.
